## Objective
Parse `foreign type` and contract-guarded `foreign operation` declarations under
`[language] version = "3"`, register `sym_` IDs under the semantic model, and
statically enforce that all external libraries referenced in `from "<library>"`
are explicitly registered in `wolio.toml [foreign] allowed_libraries`, rejecting
unauthorized libraries with compile-time diagnostic `WOLIO-FOREIGN-001`.

## Self-contained implementation context
- **Grammar and AST (`crates/wolio-ast`, `crates/wolio-parser`):**
  - Foreign type syntax:
    ```text
    foreign_type_decl = [ "pub" ], "foreign", "type", ident, "from", string_lit, ";" ;
    ```
    ```rust
    pub struct ForeignTypeDecl {
        pub span: Span,
        pub name: Spanned<String>,
        pub library: Spanned<String>,
        pub public: bool,
    }
    ```
  - Foreign operation syntax:
    ```text
    foreign_op_decl = [ "pub" ], "foreign", "operation", ident, "(", [ fields ], ")", "->", type, "from", string_lit, "{", { contract_clause }, "}" ;
    ```
    ```rust
    pub struct ForeignOpDecl {
        pub span: Span,
        pub name: Spanned<String>,
        pub library: Spanned<String>,
        pub params: Vec<FieldDecl>,
        pub return_type: TypeAst,
        pub requires_clause: Option<Box<Expr>>,
        pub ensures_clause: Option<Box<Expr>>,
        pub effects_clause: Vec<Spanned<String>>,
        pub errors_clause: Vec<Spanned<String>>,
        pub public: bool,
    }
    ```
  - Foreign operations cannot contain an `implementation { ... }` block; the body is generated by the compiler's C glue generator (`T318`).
  - Under `[language] version = "1"` or `"2"`, parsing `foreign` emits `WOLIO-FEATURE-001`.
- **Manifest validation rules (`crates/wolio-semantic::resolver`, `crates/wolio-semantic::graph`):**
  - In `wolio.toml`:
    ```toml
    [foreign]
    allowed_libraries = ["libhardware", "libsqlite3"]
    ```
  - For every `foreign type ... from "<lib>";` and `foreign operation ... from "<lib>"`, `<lib>` must be present in `[foreign].allowed_libraries`.
  - If `[foreign]` is omitted or `<lib>` is not in `allowed_libraries`, compiler emits:
    ```json
    {
      "code": "WOLIO-FOREIGN-001",
      "severity": "error",
      "message": "Unauthorized foreign library '<lib>'",
      "violation": {
        "library": "<lib>",
        "allowed_libraries": [...]
      }
    }
    ```
  - Normalized `[foreign].allowed_libraries` is hashed into the project policy snapshot hash.
  - Adding or modifying `[foreign]` requires `HUMAN_REQUIRED` approval.
- **Identity & Resolution (`crates/wolio-semantic::resolver`, `crates/wolio-semantic::graph`):**
  - Foreign types and operations receive unique `sym_` IDs under hash domain `"wolio.symbol.v1"` with kinds `"foreign_type"` and `"foreign_op"`.
  - Public foreign types and operations can be imported and referenced across modules in the same project.

## Scope
In scope:
- Parsing `foreign type` and `foreign operation` declarations in `wolio-parser`.
- AST definitions in `wolio-ast`.
- Manifest parsing of `[foreign].allowed_libraries` and validation in `wolio-semantic::resolver`.
- Emitting `WOLIO-FOREIGN-001` for unauthorized libraries.
- Snapshot hashing and `sym_` ID generation for foreign symbols.

Out of scope (owner):
- Type checking linear non-storability (`WOLIO-FOREIGN-002`) and fixed-width integers (T317).
- Contract boundary wrapper generation and error marshalling (T318).
- LLVM lowering, linking, and `with_mock` test dispatch (T319).

## Normative requirements
- Any foreign type or operation referencing a library not declared in `wolio.toml [foreign] allowed_libraries` must fail compilation with `WOLIO-FOREIGN-001` (CORE_V3, DIAGNOSTIC_SPEC).
- Using `foreign` declarations under `[language] version = "1"` or `"2"` must fail with `WOLIO-FEATURE-001` (CORE_V3, EXTENSION_BOUNDARIES).
- Foreign declarations cannot define an `implementation { ... }` block in Wolio source (CORE_V3).

## Acceptance criteria
Positive and boundary:
- [ ] Valid `foreign type DeviceHandle from "libhardware";` parses and binds `sym_` ID with `kind = "foreign_type"`
- [ ] Valid `foreign operation ReadRegister(...) -> Result<UInt8, ForeignError> from "libhardware" { ... }` parses without implementation body
- [ ] Multiple libraries listed in `[foreign].allowed_libraries = ["liba", "libb"]` pass verification when both are used

Rejection and failure:
- [ ] Using a library not in `allowed_libraries` fails compilation with `WOLIO-FOREIGN-001`
- [ ] Declaring `foreign` under `[language] version = "1"` or `"2"` fails with `WOLIO-FEATURE-001`
- [ ] Providing an `implementation { ... }` block for a `foreign operation` fails syntax check with `WOLIO-SYNTAX-001`

Completion:
